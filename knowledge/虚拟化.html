虚拟化（Virtualization）

一句话本质
Hypervisor 坐在硬件和操作系统之间，把一台物理机的资源隔离切分成多台虚拟机，每台以为自己独占整台电脑。

第一幕：问题感知

你是一家银行的 IT 主管。机房里整整齐齐摆了 40 台服务器。

第一台跑工资系统——每月月底忙三天，其余 27 天几乎空转。CPU 使用率：8%。

第二台跑邮件——白天有点活儿，晚上闲着。CPU 使用率：12%。

第三台跑官网——偶尔有人访问。CPU 使用率：3%。

40 台服务器，平均利用率不到 15%。但你不敢把工资系统和邮件装在同一台机器上——上次有人试过，邮件系统崩了，把工资系统一起拖死了，全行三千人那个月差点没发出工资。

所以每个应用必须独占一台物理机。这是铁律。

电费账单到了。40 台机器，每台功耗 400 瓦，全年无休。加上空调散热，年电费超过 70 万。而这些机器 85% 的时间在空转——你在用真金白银给空气加热。

领导找你谈话："能不能砍到 10 台机器？"

你说不行，应用之间会互相干扰。

领导说："那就想个办法，让它们装在一起但互不干扰。"

怎么让一台机器安全地装下多个系统？

第二幕：引导式构建

先想清楚"互相干扰"到底在干扰什么。工资系统崩溃拖死邮件系统，根子在于它们共享同一个操作系统。一个程序吃光了内存，另一个就饿死了。一个程序让系统内核崩溃，所有程序一起陪葬。

所以真正的需求是：每个应用以为自己独占一整台电脑，拥有自己的操作系统、自己的内存、自己的硬盘，互相完全看不见。但物理上，它们确实跑在同一块硬件上。

换句话说，我们要造出假的电脑，假到连操作系统都分辨不出真假。

想一想：如果你要"假装"出一台电脑，至少需要骗过哪些东西？CPU？内存？硬盘？网卡？谁来负责"演这出戏"？

既然操作系统以为自己在独占硬件，就需要一个中间人，坐在真正的硬件和多个操作系统之间，截获所有对硬件的请求，然后巧妙地分配和隔离。

这个中间人叫 Hypervisor（虚拟机监控器）。"Hyper"意为"超越"——它超越了普通的操作系统，站在更底层的位置来调度一切。

打个比方。一栋大楼（物理服务器）原来只住一户人家（一个操作系统）。现在请来一个物业管理公司（Hypervisor），把大楼改造成多个独立公寓。每户有自己的门锁、自己的电表、自己的水管。住在三楼的人完全不知道五楼住了谁，也碰不到五楼的东西。

每一个"独立公寓"就是一台 虚拟机（Virtual Machine, VM）。

想一想：这个"物业公司"应该装在哪里？是直接装在大楼的地基上，还是装在某一户人家里面？这两种方式会有什么不同？

这个问题正好对应两种截然不同的架构。

第一种：把 Hypervisor 直接装在裸硬件上，它自己就是最底层的"操作系统"，所有虚拟机都运行在它之上。这叫 Type 1——裸金属型（Bare-metal）。就像物业公司直接拥有这栋楼，从打地基开始就是它在管。VMware ESXi、微软 Hyper-V 就是这一类。银行和云计算中心几乎都用这种——中间没有多余的层，性能损耗最小，隔离最干净。

第二种：先装一个普通操作系统（比如 Windows 或 Linux），然后在里面装一个软件来创建虚拟机。这叫 Type 2——宿主型（Hosted）。就像你在自己家里腾出几个房间隔成小隔间转租出去。VMware Workstation、VirtualBox 就是这一类。方便，但多了一层"房东"在中间转手，性能打折扣。

想一想：如果你是银行 IT 主管，要在生产环境里跑 40 个关键业务系统，你会选哪种？如果你只是想在 Mac 上临时试一下 Windows，又会选哪种？

Hypervisor 到位了，但"分公寓"不是画条线就完事的。你得明确每户能用多少资源。

先说 CPU。一台物理机有 8 个 CPU 核心。你可以给虚拟机 A 分配 2 个虚拟 CPU（vCPU），给 B 分配 4 个，给 C 分配 2 个。Hypervisor 在底层调度，确保 A 只能使用分配给它的那份算力。你甚至可以"超卖"：8 个物理核心分出 12 个 vCPU，赌的是它们不会同时全力运转——就像航空公司超售机票。

再说 内存。物理机有 64GB，你给 A 划 16GB、B 划 32GB、C 划 16GB。A 的程序试图读取 16GB 之外的地址？Hypervisor 直接拦截。B 永远看不到 A 的内存里有什么。

硬盘也类似。Hypervisor 为每个虚拟机创建一个虚拟磁盘文件——本质上就是物理硬盘上的一个大文件，但虚拟机看起来就是一整块独立硬盘。

想一想：超卖 CPU 听起来很聪明，但什么场景下会翻车？如果三个虚拟机同时跑满，会发生什么？

每台虚拟机还需要上网、互相通信。但物理机可能只有一块网卡。

Hypervisor 在软件层面造出一个 虚拟交换机（Virtual Switch）。每台虚拟机获得一块虚拟网卡（vNIC），拥有自己的 MAC 地址和 IP 地址。虚拟机 A 给虚拟机 B 发数据包，虚拟交换机在内部直接转发，不需要真的跑出物理机再绕回来。要访问外网？虚拟交换机把流量导向物理网卡，送出去。

想一想：如果你想让虚拟机 A 和虚拟机 B 完全网络隔离（即使在同一台物理机上也互相 ping 不通），虚拟交换机该怎么配置？

虚拟机比物理机多了一个魔法般的能力。

既然整台虚拟机就是一堆文件（虚拟磁盘 + 配置文件 + 内存状态），那你可以在任意时刻给它拍一张 快照（Snapshot）——完整保存当前 CPU 寄存器状态、内存内容、磁盘数据。之后搞砸了，一键回滚到快照那一刻。就像游戏里的存档读档。

更厉害的是 迁移（Migration）。把虚拟机的全部文件从物理机 A 拷贝到物理机 B，在 B 上启动——虚拟机"搬家"了。甚至有热迁移（Live Migration）：Hypervisor 先同步磁盘和大部分内存，最后在极短的一瞬间暂停源端，把最后一点变化同步过去，在目标端恢复运行。用户几乎无感知。

想一想：快照占空间吗？如果连续拍了 10 个快照，会发生什么？

第三幕：完整组装

一台物理机跑三个虚拟机的完整架构

+==============================================================+
|                 物理服务器 (Physical Server)                    |
|  CPU: 8核   内存: 64GB   硬盘: 2TB   网卡: 1块千兆             |
+==============================================================+
|                                                                |
|  +----------------+  +----------------+  +----------------+    |
|  |  VM-A (工资)    |  |  VM-B (邮件)    |  |  VM-C (官网)    |    |
|  |  CentOS 7      |  |  Ubuntu 20.04  |  |  Windows 2019  |    |
|  |  vCPU:2         |  |  vCPU:4         |  |  vCPU:2         |    |
|  |  vRAM:16GB      |  |  vRAM:32GB      |  |  vRAM:16GB      |    |
|  |  vDisk:200GB    |  |  vDisk:500GB    |  |  vDisk:300GB    |    |
|  +-------+--------+  +-------+--------+  +-------+--------+    |
|          |                    |                    |            |
|  +-------|--------------------|--------------------|--------+  |
|  |             虚拟交换机 (Virtual Switch)                    |  |
|  +----------------------------|-------------------------------+  |
|                               |                                |

|  |              Hypervisor (Type 1 / 裸金属)                   |  |

+===============================|================================+

                    +-----------+-----------+

                    +-----------------------+

结果：40 台物理机 -> 10 台。电费从 70 万降到不到 20 万。工资系统崩了？邮件系统毫无感觉——它们连操作系统都不是同一个。

组件检查

组件 在示例中的位置
Hypervisor ESXi 装在物理机上，管理一切
Type 1 vs Type 2 生产环境选 Type 1（裸金属）
vCPU / vRAM / vDisk 每个 VM 独立分配
虚拟交换机 VLAN 隔离工资+邮件 vs 官网
快照 升级前拍初始稳定版
迁移 物理机维修时把 VM 热迁走

第四幕：验证与压力测试

反事实：不用 Hypervisor，直接在一个 Linux 上跑不同应用？

能隔离权限，但隔离不了故障。一个应用触发内核崩溃，整台机器所有应用全灭。虚拟化的隔离发生在硬件抽象层，每个虚拟机有自己独立的内核，一个内核崩不影响另一个。

边界：虚拟化的开销

性能税：早期纯软件虚拟化性能损失 20-30%。Intel VT-x / AMD-V 硬件辅助虚拟化把开销压到 2-5%，但始终不是零。

内存税：每个虚拟机跑完整操作系统内核。三个 VM = 三份内核在内存里。

启动税：新建虚拟机从开机到就绪要几十秒到几分钟。

连接

虚拟化 -> VPS / 云服务器：VPS与云服务器 底层就是 Hypervisor 切出的虚拟机。

虚拟化 -> 容器：容器与虚拟机 是虚拟化的轻量级演进——共享内核代替独占内核。
