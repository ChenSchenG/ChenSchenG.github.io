子网（Subnet）

一句话本质
子网通过操纵子网掩码（借位）将一个大网络划分为多个小网络，实现广播隔离和安全分区。

第一幕：问题感知

你在一家小公司上班，办公室 20 个人，共用一个网络。你发一条消息给同事老王，消息顺利到达，一切正常。

公司壮大了。200 人，2000 人，20000 台设备——全挂在同一个网络上。

现在问题来了：你发给老王的消息，网络会把它喊给所有 20000 台设备。每台设备都要停下手头的事，拆开看一眼："这是给我的吗？不是。扔掉。" 然后继续干活。

20000 台设备，每秒钟都在互相喊话。每台设备都在不停地拆别人的信。网络淹没在噪音里，越来越慢。

更麻烦的是——财务部的工资数据、研发部的核心代码、前台的访客 WiFi，全在一个锅里。谁都能听到谁的喊话。

你大概会想到：隔开。把大网络分成几个小区域，就像把一个巨大的敞厅隔成一间间办公室——财务一间、研发一间、前台一间。喊话只在自己房间里传播。

但网络不是物理空间，没有砖墙。所有电脑共享同一根网线（或同一个交换机）。

怎么在一张平坦的网络上，画出看不见的墙？

第二幕：引导式构建

要画墙，先得知道"地址"长什么样——不然你都不知道在哪里画。

每台联网设备都有一个 IP 地址（Internet Protocol address），比如 192.168.1.37。四个数字，用点隔开，每个数字范围 0–255。

这个地址不是随便取的。它其实藏着两层信息：你住哪条街和你是这条街的几号门牌。

"街道"部分叫网络前缀（network portion），"门牌"部分叫主机地址（host portion）。同一条街上的设备可以直接通信，不同街的要通过路由器中转。

想一想：如果 192.168.1.37 和 192.168.1.200 在同一条"街"上，那"街道"是哪部分，"门牌"又是哪部分？

问题来了：光看 192.168.1.37 这串数字，你分不出哪里是街道、哪里是门牌。192 是街道吗？192.168 是？还是 192.168.1？

必须有一个东西告诉计算机：从哪里切一刀。

这个东西叫子网掩码（Subnet Mask）。它的格式和 IP 地址一样，也是四个数字，比如 255.255.255.0。

掩码的规则极其简单：255 对应的位置是街道，0 对应的位置是门牌。

拿 255.255.255.0 来说——前三段是 255，最后一段是 0。意思是：IP 地址的前三段（192.168.1）是街道，最后一段（.37）是门牌。

想一想：如果掩码是 255.255.0.0，那 172.16.5.99 的"街道"是什么，"门牌"是什么？

到这里，你知道了怎么读地址。但第一幕的问题还没解决——怎么把一条大街拆成几条小巷？

回到那个 20000 人的公司。假设公司拿到一个网络：192.168.1.x，掩码 255.255.255.0。最后一段 0–255 共 256 个地址，所有设备挤在一条街上。

我们想把这条街拆成 4 条小巷，分给 4 个部门。

关键洞察：掩码里的 255 不是铁板一块。 我们可以把它"往右推"——把原本属于门牌的位置，借一部分过来当街道。

要理解"借"，需要看一层更底层的东西。255 在计算机里是 8 个 1：11111111。0 是 8 个 0：00000000。所以 255.255.255.0 用二进制写就是：

11111111.11111111.11111111.00000000
|<------- 街道（24位）------->|<门牌(8位)>|

24 个 1，8 个 0。1 的部分 = 街道，0 的部分 = 门牌。

现在，我们从门牌区借 2 位给街道：

11111111.11111111.11111111.11000000
|<------- 街道（26位）----------->|<门牌(6位)>|

26 个 1，6 个 0。街道变长了，门牌变短了。

想一想：借了 2 位之后，门牌区还剩 6 位。6 位二进制最多表示多少个不同的数？（提示：$2^6 = ?$）

$2^6 = 64$。每条小巷最多 64 个地址。

那一共几条小巷？借的 2 位可以表示 $2^2 = 4$ 种组合（00, 01, 10, 11），正好 4 条。

借的 2 位 小巷编号 地址范围
00 小巷 0 192.168.1.0 – 192.168.1.63
01 小巷 1 192.168.1.64 – 192.168.1.127
10 小巷 2 192.168.1.128 – 192.168.1.191
11 小巷 3 192.168.1.192 – 192.168.1.255

原来一条 256 人的大街，变成了 4 条各 64 人的小巷。每条小巷就是一个子网（Subnet）。

这就是"子网"这个名字的由来——从一个网络中划分出来的子网络。

想一想：如果我们借 3 位而不是 2 位，会得到几条小巷？每条小巷多少个地址？

还有一个记法上的便利。255.255.255.192 写起来太长，而它本质上就是"前 26 位是 1"。所以人们直接在 IP 地址后面加一个斜杠写法：

$$192.168.1.0/26$$

/26 就是说"前 26 位是街道"。这种写法叫 CIDR 记法（Classless Inter-Domain Routing，无类别域间路由）。/24 对应 255.255.255.0，/26 对应 255.255.255.192，以此类推。

最后一个细节：每条小巷 64 个地址，但不是 64 个都能分给设备。

每条小巷有两个特殊地址被占用：第一个地址（全 0 门牌）是子网标识地址（Network Address）——它是这条小巷的"路牌"，路由器靠它识别整条小巷的存在，不分配给任何设备；最后一个地址（全 1 门牌）是广播地址（Broadcast Address）——它是小巷里的"大喇叭"，发到这个地址的消息会被转发给小巷里的所有设备（正是第一幕"喊话"的正规版本）。

注意：这里的"子网标识地址"和前面说的"网络前缀（街道部分）"不是一回事——前者是一个完整的 IP 地址（如 192.168.1.0），后者是 IP 地址中用来标识街道归属的那几位。

以小巷 0 为例：

  • 192.168.1.0 → 子网标识地址（不能分配）
  • 192.168.1.63 → 广播地址（不能分配）
  • 192.168.1.1 – 192.168.1.62 → 可用地址，共 62 台设备

公式：可用主机数 = $2^{主机位数} - 2$

想一想：一个 /28 的子网，主机位有多少位？最多能接几台设备？

第三幕：完整组装

所有零件到齐了，拼成全景：

          一个 /24 网络（256 个地址）
          192.168.1.0 ~ 192.168.1.255
                      |
            借 2 位 → /26 掩码
                      |
     +--------+--------+--------+--------+
     |        |        |        |        |
  子网 0    子网 1    子网 2    子网 3
  .0-.63   .64-.127  .128-.191 .192-.255
  62台可用  62台可用   62台可用   62台可用

端到端示例：公司拿到网络 10.0.0.0/24，要分给 3 个部门，每个部门最多 50 台设备。

第一步：确定需要借几位。

  • 3 个部门 → 至少 3 个子网 → 借 2 位得到 4 个子网（$2^2 = 4 \geq 3$，够了）
  • 每个子网：$2^6 - 2 = 62$ 台可用 → $62 \geq 50$，够了
  • 新掩码：$/26$，即 255.255.255.192

第二步：算出每个子网的范围。

子网 子网标识地址 可用范围 广播地址 分配给
0 10.0.0.0 .1 – .62 10.0.0.63 财务部
1 10.0.0.64 .65 – .126 10.0.0.127 研发部
2 10.0.0.128 .129 – .190 10.0.0.191 前台
3 10.0.0.192 .193 – .254 10.0.0.255 备用

想一想：研发部的 10.0.0.100 发广播，能到达财务部的 10.0.0.10 吗？为什么？

第三步：验证隔离。
财务部的 10.0.0.10 发广播 → 广播只到 10.0.0.63（子网 0 的广播地址）→ 路由器检查源地址和目标地址的网络位，发现两者不在同一子网，广播不会被转发出去 → 研发部的 10.0.0.100 收不到。墙生效了。

组装检查：

  • ✅ IP 地址结构 → 确定"街道"和"门牌"
  • ✅ 子网掩码 → 告诉计算机在哪里切
  • ✅ 借位 → 从门牌区借位给街道区，创造子网
  • ✅ CIDR → /26 简写
  • ✅ 子网标识地址 & 广播地址 → 首尾两个特殊地址
  • ✅ 可用主机数 → $2^n - 2$

第四幕：验证与压力测试

1. 反事实——如果去掉子网掩码？
计算机看到 192.168.1.37 和 192.168.1.200，不知道它们是在同一个网络还是不同网络。无法判断"直接发"还是"交给路由器"。网络瘫痪。掩码是计算机唯一的切割依据。

2. 边界——能借到什么极端？

  • 借到只剩 2 位主机 → $/30$，$2^2 - 2 = 2$ 台可用。这在实际中用于点对点链路（两个路由器之间的连线，只需要 2 个地址）。
  • 借到只剩 1 位 → $/31$，理论上 0 台可用。但 RFC 3021 特别允许点对点链路使用 /31，省下 2 个地址。
  • 借到只剩 0 位 → $/32$，一个地址指一台设备，常见于路由表和防火墙规则中。

想一想：如果完全不借位（保持 /24），会怎样？——回到第一幕的大敞厅，所有人又挤在同一条街上喊话。

3. 连接——子网和 VLAN 是什么关系？

延伸阅读
子网是逻辑上的划分（在 IP 层画墙），VLAN 是物理/链路层的划分（在交换机上画墙）。实际网络中，通常一个 VLAN 对应一个子网——VLAN 负责隔离电信号，子网负责隔离 IP 通信。两者配合，墙才真正挡住。

4. 终极挑战——空白重建路线图：

[一张大网所有人互相喊话，太吵太乱]
        |
[需要一种"地址结构"来区分归属]
        |
[IP 地址 = 街道 + 门牌]
        |
[缺一个东西告诉计算机哪里是街道哪里是门牌]
        |
[子网掩码：1 = 街道，0 = 门牌]
        |
[把门牌位借一部分给街道 → 一条大街变多条小巷]
        |
[每条小巷 = 一个子网，首尾地址保留]
        |
[完成：广播隔离，安全分区，地址有序]
